# Fleet rules

- Historical exercises use a shared numeric bucket for manual entry and aggregation; retain imported source years and debt keys for audit and deduplication, displaying their bucket label instead of rewriting consultation data.

- Document/fine status (vencido, a vencer em 30 dias, em dia) comes from the due date in `fleetDocumentStatus.ts`, not the stored status alone, so stale records still show as overdue.
- Detran debts use dedicated endpoints in `normalize.ts` and `[detran:<key>]` updates; MA includes SEFAZ debts in the Detran response, while TO sources run independently in parallel. `resultado.ts` preserves partial results and records failures in history; MA/TO never infer payment from absence or retry automatically, because omitted records are not proof of payment. GO retains IPVA-only absence settlement; failed/partial history never makes a vehicle clean.
- Detran owner documents resolve canonical profile IDs first and legacy auth IDs only when unique, both in the dialog and server; the stored owner's document takes precedence to avoid querying another establishment.
- The selected-vehicles report (`fleetRelacaoPdf.ts`) prints A4 landscape (the column set needs the width) with manual `.doc-page` pagination sized from row heights measured in the browser, so no vehicle block is split across a page break; keep the height constants in sync with the rendered HTML and measure cell text with the canvas helper instead of guessing characters per line. Value columns carry no `R$` in the cells — the symbol is in each column header — so every money column fits the page; short fixed tokens (ano, UF, RENAVAM) stay on one line and long text breaks at spaces only.
