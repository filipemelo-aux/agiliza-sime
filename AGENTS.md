# Project architecture rules

- Reports use HTML windows and foreign-object capture with isolated batch pages; `pdfImages.ts` decodes and paints images directly to avoid SVG image races. DACTE uses `dactePdf.ts` vectors; cheques use stored `checkPdf.ts` layouts, preserving geometry.
- Long fiscal entry forms are composed from collapsible section blocks and tinted sub-groups, with fields placed inside the block that owns the data, so density stays high while collapsed sections keep their state.
- ANTT minimum-freight coefficients live as versioned constants in one module, and road distance comes from a backend function, so a new ANTT resolution only adds a table version.
- CT-e authorization is initiated only from the list toolbar and uses the Focus NFe backend connector; fiscal forms only save drafts.
- CT-e talões share DACTE and must open Other payer fields with inline person creation; service actors use CteActorSection.
- DAMDFE uses only `damdfePdf.ts` vectors (A4 landscape, approved geometry), never HTML/canvas or Focus PDF, for identical prints.
- SEFAZ operations on a CT-e (transmit, status, DACTE PDF, XML, CC-e, cancel) are grouped in one dialog opened by the toolbar SEFAZ button; the focus-nfe function exposes them per saved CT-e id keeping the environment consistent.
- CT-e CFOP is derived centrally from the service origin/destination states and service type, so route changes cannot leave an internal/interstate code inconsistent.
- Official fiscal glyphs (SEFAZ, MDF-e) come from the Sime SVG set stored as CDN assets and are exposed only through wrapper components in `src/components/icons`, for reuse .
- Operational tables use tenant_id and RESTRICTIVE tenant_isolation. Server has_role permits admin/moderator/operador operations, not admin equivalence; numbering and certificate reads scope tenant, and loading effects depend on resolved access.
- App branding uses useTenant; login stays neutral. SuperAdmin has_role('admin') applies only in tenant-scoped support mode.
- Page-level search, period, ordering, and filter controls live in the collapsed-by-default `SearchFilterCard` titled “Filtrar”; its first row keeps the period at the left edge and the company filter (“Todas as Empresas”) at the right edge; `GlobalToolbar` is reserved for operational icon actions and non-interactive selection context.
- Received NF-es are cached in `nfes_recebidas` (incremental Focus `versao` sync, actor derived from XML) and reused by expense/CT-e dialogs via an `initialXml` prop, so SEFAZ is queried once per note.
- Focus NFe tokens are stored per fiscal establishment in service-role-only `establishment_secrets` (falling back to tenant_secrets/env), managed only from SuperAdmin; tenant users can only upload/replace the A1 certificate, which `certificate-manager` validates (node-forge) and pushes to Focus via `_shared/focusCertificate.ts` with the account master token, so emission credentials never reach tenant UIs.
- Every A1 certificate upload (tenant settings, SuperAdmin company, SuperAdmin branch) goes through `registerCertificate` in `supabase/functions/_shared/focusCertificate.ts`, so validation, storage in fiscal_certificates, establishment links and Focus sync never diverge between entry points.
- Plate inputs mask by position in `maskPlateInput`: 3 letters, digit, letter-or-digit, 2 digits — so both Mercosul (ABC1D23) and old-format (ABC1234) plates can be typed; validation (`validatePlate`) accepts both.
- Each vehicle is an independent plate with a unit category and owner; operational assignments own drivers and implement composition, projecting legacy fields transactionally to preserve existing fiscal and operational consumers.
- DialogContent owns default padding and vertical scrolling directly, without a nested scrolling wrapper; dialogs with their own body scroller override it with overflow-hidden so each window has only one primary scroll area.
- Print headers (except DACTE/DAMDFE/cheques) use `buildPrintHeaderHtml` with the document's establishment; contracts use its invoice layout to match faturas without changing other reports.
- Brand footers share `printBrand.ts` assets and physical sizes; cheques remain isolated.
- Freight contracts use fixed wrapping tables, matching A4 margins and an unbreakable signature/brand closing block with compact print spacing to prevent orphaned logos; `fiscalProtocol.ts` extracts protocol numbers to prevent overflow.
- MDF-e printing resolves missing driver snapshots through `mdfeDrivers.ts` and profile IDs, so old manifests gain CPFs without altering authorized data.
- Financial reads wait for auth, paginate with fetchAllRows and surface errors; edits reuse payment-state triggers. Receivables grid uses receivableBalance.ts for cent-rounded remaining principal and visible-row totals, separate from original values.
- Expense composition uses expenseComposition.ts totals; combined parts/service keeps separate payable IDs and aggregates only maintenance cost to avoid double-counting.
- Accounting uses `contabilidadeExport.ts` for due-month debt, payment-month history, account filters, agencies, CT-e types and contracts; bank reports use `payableReportState.ts` for disjoint due filters and principal balances.
